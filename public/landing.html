Built for the events that don't fit a simple RSVP

The details that make an all-nighter or a five-session cohort behave like one clean record.

A session that starts at 9pm and runs to 6am the next morning is tracked as a single window. A student checking in at 1am still lands inside that same session — not a phantom second day.

Set a default session shape once for a whole program — say, weekly Thursday workshops — and every new event created under it inherits the same window, instead of being configured from scratch each time.

Every digital pass carries a token that's locked to one session's exact check-in window. Scan it before doors open or after they close and it reads as out-of-window, not as a valid check-in.

Staff can still check someone in after a window closes — a stuck bus, a late flight — and it's logged distinctly from an on-time scan, so the record stays honest without losing the student.

How a pass locks to its window

Every digital pass carries a token tied to one session, not just one student.

Issued

A pass is generated for a student and a specific session — its token only means something for that pairing.

Locked to the window

The token becomes scannable only once that session's check-in window opens.

Scanned

At the door, the scanner reads the token and checks it against the live window — not just whether it's a real pass.

Confirmed

A valid scan inside the window checks the student in and syncs instantly — outside it, the desk falls back to a manual, logged check-in.
